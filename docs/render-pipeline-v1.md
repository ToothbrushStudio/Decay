# Decay Render Pipeline — Version 1 (pipeline id `0x01`)

*Status: frozen upon merge, like the payload format. The decoder regenerates
this pipeline's op sequence bit-for-bit to play the reverse ("un-rot")
animation, so any behavioral change to this spec breaks the animation for
every existing pipeline-1 image. Improvements ship as pipeline id 2+; images
declaring an unknown pipeline id still decrypt, with no animation.*

---

## Concept

The art is the message. The decay applied to a carrier image is a sequence of
**invertible** pixel operations derived deterministically from the sealed
payload container. Because every op is a bijection on the pixel data:

- The **encoder** applies all ops to the carrier; the final frame is the
  exported image (payload embedded afterwards, watermark after that).
- The **decoder** extracts the container, re-derives the identical op
  sequence, and applies the inverses in reverse order — the received image
  genuinely un-rots back to the sender's carrier while the message is
  revealed. No original carrier, no stored frames, no extra data.

Residue after un-rot is intentional: the payload's LSB embedding (≤ ±3 per
channel, invisible) and any Free-tier watermark remain, scattered by the
inverse ops.

Only this pipeline must be cross-platform deterministic; it therefore uses
**integer math only**. Carrier presets (Decay.Renderer) are generated once at
encode time and never regenerated by a decoder, so they carry no such
constraint.

## Structure

- **120 ops** total, grouped as **40 frames × 3 ops**. Frame `f` consists of
  ops `[3f, 3f+3)`. Forward playback applies frames 0→39 to the carrier;
  reverse playback inverts ops 119→0 starting from the received image.
- **Intensity ramp:** each op is scaled by `ramp = f + 1` out of 40, so the
  rot escalates — Erosion-mild at the start, Necrosis-violent at the end.

## Random stream

- Seed: `SHA-256(container bytes)` — the full sealed container, header
  through tag. Both sides possess it exactly.
- Generator: **xoshiro256\*\*** with its state initialized from the 32-byte
  hash read as four little-endian u64s (in the extraordinarily unlikely
  all-zero case, state[0] is set to `0x9E3779B97F4A7C15`).
- `Draw(bound)` = `Next() % bound` (modulo bias is irrelevant here;
  determinism is what matters).

All draws happen at **op-generation time** in the exact order below, with a
fixed number of draws per op kind — degenerate parameters make an op a no-op
at apply time but never change the draw sequence.

## Op stream

For each op index `0..119`: draw `kind = Draw(5)`, then that kind's
parameters, in order. Fractions are in units of 1/10000 of the image
dimension and resolve to pixels via integer math: `x = fx * W / 10000`,
sizes clamped to a minimum of 1 and clipped to the image edge.

| Kind | Name | Parameter draws (in order) | Apply | Invert |
|---|---|---|---|---|
| 0 | NoiseXor | `fx=Draw(10000)`, `fy=Draw(10000)`, `fw=1000+Draw(4000)`, `fh=1000+Draw(4000)`, `subSeed=Next()`, `densityBase=32+Draw(96)` | XOR a deterministic noise field over the rect (see below), density = `densityBase * ramp / 40`, min 8 | Same op (XOR is self-inverse) |
| 1 | BandShift | `fy=Draw(10000)`, `fh=500+Draw(2000)`, `fdx=100+Draw(2400)` | Cyclic-shift each row of the horizontal band right by `dx = fdx * W * ramp / 400000` pixels (mod W; no-op if 0) | Shift left by `dx` |
| 2 | ColumnShift | `fx=Draw(10000)`, `fw=500+Draw(2000)`, `fdy=100+Draw(2400)` | Cyclic-shift each column of the vertical band down by `dy = fdy * H * ramp / 400000` (mod H; no-op if 0) | Shift up by `dy` |
| 3 | BlockSwap | `fx1=Draw(10000)`, `fy1=Draw(10000)`, `fx2=Draw(10000)`, `fy2=Draw(10000)`, `fw=500+Draw(1500)`, `fh=500+Draw(1500)` | Swap the pixel content of two equal-size rects, both clipped to the smaller of the two fits; **no-op if the rects intersect** | Same op (disjoint swap is an involution) |
| 4 | ChannelShift | `fy=Draw(10000)`, `fh=500+Draw(2000)`, `channel=Draw(3)`, `fdx=100+Draw(2400)` | Within each row of the band, cyclic-shift only the given channel's values right by `dx = fdx * W * ramp / 400000` (mod W; no-op if 0) | Shift that channel left by `dx` |

All ops touch R, G, B (BandShift/ColumnShift/BlockSwap move whole RGBA
pixels; alpha is uniformly 255 so this is moot). NoiseXor and ChannelShift
never touch alpha.

### NoiseXor noise field

A sub-generator, xoshiro256\*\* seeded from `subSeed` via four rounds of
**splitmix64**, is stepped once per pixel of the rect in row-major order.
Per pixel, with draw `r`:

- gate byte `r & 0xFF`: the pixel is hit iff `gate < density`
- if hit: `R ^= (r >> 8) & 0xFF`, `G ^= (r >> 16) & 0xFF`,
  `B ^= (r >> 24) & 0xFF`

## Why these ops (and only these)

Every op preserves the *magnitude* of a small pixel perturbation: XOR
inverses cancel exactly, and the movement ops relocate bytes without
arithmetic on them. This is what keeps the post-embed LSB deltas invisible
after un-rot. Ops that amplify low bits — bit rotations, multiplies,
saturating arithmetic — are excluded by design. Additive ops (mod-256) were
excluded for wrap-around speckle. Keep this property in mind for pipeline 2.

## Aesthetic coverage

NoiseXor = static/erosion · Band/ColumnShift = tears and smears ·
BlockSwap = datamosh displacement · ChannelShift = chromatic bleed.
The carrier preset (chosen by stage: Erosion / Corruption / Necrosis) sets
the identity; the op pipeline provides the rot.
